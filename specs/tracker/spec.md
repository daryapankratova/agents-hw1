# Tracker Specification (specs/tracker/spec.md)

## MUST Requirements

- [MUST] Трекер реализован в одном файле `tracker-v2.html` с встроенными CSS и JavaScript (без внешних библиотек, CDN, API-ключей).
- [MUST] Данные задачи содержат поля: `id`, `title`, `hours`, `done`.
- [MUST] Операции добавления, удаления и переключения `done` реально изменяют внутреннее состояние списка задач.
- [MUST] Поле `title` после `.trim()` не должно быть пустым; при ошибке отображается сообщение рядом с полем.
- [MUST] Поле `hours` — число в диапазоне 0,5–24 с шагом 0,5; пустое значение не считается нулём. При нарушении диапазона или формата отображается ошибка рядом с полем, данные формы сохраняются.
- [MUST] Прогресс рассчитывается по формуле: `округление(100 × сумма часов done / сумма часов всех задач)`. Если задач нет — прогресс 0%. Не допускаются значения NaN или Infinity.
- [MUST] Фильтр влияет только на видимый список задач; итоговые часы и прогресс считаются по всем задачам (включая скрытые фильтром).
- [MUST] Интерфейс читаем на минимальной ширине 390 px без горизонтального скролла; все поля и кнопки имеют понятные подписи.
- [MUST] При недоступности localStorage отображается понятное сообщение; трекер продолжает работать в памяти.

## WHEN/THEN Scenarios

- WHEN пользователь включает фильтр «активные», THEN в списке отображаются только задачи с `done = false`; прогресс и итоговые часы остаются неизменными.
- WHEN в поле названия введено пустое значение (после trim) или в поле часов введено пустое/отрицательное/некорректное значение, THEN задача не добавляется в список; рядом с соответствующим полем отображается ошибка; введённые данные в форме сохраняются.
- WHEN все задачи удалены из списка, THEN итоговые часы равны 0 ч, прогресс равен 0%; интерфейс корректно отображает эти значения.
- WHEN задача «Практика» (4 ч) переключается в состояние `done = true` (при стартовом наборе: «Чтение» — 2 ч, done=true; «Практика» — 4 ч, done=false; «Повторение» — 2 ч, done=false), THEN прогресс должен стать 75% (6/8 часов выполнено).

## Constraints & Edge Cases

- Не допускается деление на ноль при расчёте прогресса.
- Ошибки валидации должны быть привязаны к конкретным полям и оставаться видимыми до исправления.
- Сохранение в localStorage не является обязательным для базовой функциональности; отсутствие хранилища не должно блокировать работу трекера.
